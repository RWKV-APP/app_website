## Release Notes 多语言同步操作日志（项目内）

本文档记录本项目在维护 `backend/data/release-notes/` 更新日志时的标准操作流程，用于让团队成员在不口述需求的情况下，也能稳定、可重复地完成「简体中文 → 多语言同步」的工作。

---

### 适用范围

- **目录**：`backend/data/release-notes/{zh-Hans,zh-Hant,en,ja,ru,ko}/`
- **文件命名**：`<build>-<version>.md`，例如 `703-4.3.2.md`
- **源语言**：默认以 `zh-Hans` 为唯一内容源（single source of truth）

---

### 目标

- **同一 build/version 的文件**在所有语言目录都存在（例如都叫 `703-4.3.2.md`）
- **内容结构一致**：版本小节顺序保持一致（例如 `4.3.2 → 4.3.1 → 4.3.0`）
- **仅语言不同**：条目含义一致，标签风格符合该语言的既有约定
- **新增 patch 时保留上一个版本文件**：例如新增 `705-4.3.4.md` 时，不要删除或改名已有的 `704-4.3.3.md`

---

### 语言与标签风格约定

- **zh-Hans**：`[新增] / [优化] / [修复]`
- **zh-Hant**：`[新增] / [優化] / [修復]`
- **en**：`[New] / [Improved] / [Fix]`
- **ja**：`[新規] / [改善] / [修正]`
- **ru**：`[Новое] / [Улучшено] / [Исправлено]`
- **ko**：`[신규] / [개선] / [수정]`

---

### 标点与格式规则（简体中文）

- **中文内容优先使用全角标点**：`（ ）`、`，`、`。`
- **避免混用**：中文句子里尽量不要出现半角括号 `()` 与半角逗号 `,`
- **专有名词**（如 `OpenAI`、`API`、`RWKV7-G1e 2.9B`）保留原样

---

### 标准流程（每次发布一个新文件时）

#### 0) 先确认本次要同步的最新 zh-Hans 文件

- 路径：`backend/data/release-notes/zh-Hans/`
- 默认以 `zh-Hans` 目录中 build/version 最新的 `.md` 文件作为本次同步源文件
- 推荐先执行以下命令定位目标文件：

```bash
ls backend/data/release-notes/zh-Hans/*.md | xargs -n1 basename | sort -V | tail -n1
```

- 其余 5 个语言目录都应新增同名文件
- 除非用户明确要求，否则不要删除、覆盖、改名上一个 patch 文件

#### 1) 编写 / 校对 zh-Hans 源文件

- 路径：`backend/data/release-notes/zh-Hans/<build>-<version>.md`
- 确认：
  - 文件名中的 build 与版本号正确
  - 最新版本小节（例如 `## 4.3.2`）在最顶部
  - 标点与术语一致（尤其是中文括号与逗号）

#### 2) 同步到所有其他语言（创建同名文件）

对每个语言目录创建同名文件（例如 `703-4.3.2.md`），内容做如下处理：

- **结构同步**：将 zh-Hans 的版本小节顺序与条目数量同步过去
- **逐条翻译**：基于该语言既有更新日志的行文风格进行翻译
- **标签对齐**：将 `[新增/优化/修复]` 替换为该语言对应标签
- **保留关键符号**：如 `␣`、代码片段、反引号包裹内容
- **不要删除上一个版本**：新版本文件是新增，不是替换；除非用户明确要求，否则不要删除、覆盖、改名上一个 patch 文件

#### 3) 快速自检

- 检查所有语言目录下都存在同名文件
- 检查上一个版本文件仍然保留
- 目视核对：
  - 最新小节是否都有
  - 条目数量是否一致
  - 关键名词/版本/平台限制等信息是否遗漏

#### 4) Git 提交与推送

- 默认先执行 `git status --short`，确认工作区中是否存在与本次发布无关的改动
- 如果工作区只包含本次 release notes 与 workflow 相关改动，则按以下顺序执行：

```bash
git add .
git commit -m "chore: sync latest release notes and update workflow"
git push
```

- 如果工作区存在无关改动，不要直接提交无关内容，应改为按路径添加，例如：

```bash
git add backend/data/release-notes docs/release-notes-workflow-log.md
git commit -m "chore: sync latest release notes and update workflow"
git push
```

#### 5) 推送后复核

- 确认远端分支已包含本次 commit
- 若当前环境是 Linux 服务器，推送前后都应再次确认没有误带服务器上的其他本地改动

---

### 典型示例（4.3.2 / 703）

该示例仅用于说明同步方式，不作为判断当前最新版本的依据；实际操作时始终以 `zh-Hans` 目录中的最新文件为准。

本次 `703-4.3.2.md` 的同步要点：

- 新增/优化项聚焦于：
  - Android 设备增加 OpenAI 兼容 API 服务器
  - App 稳定性提升
- 其它语言文件也必须是 **`703-4.3.2.md`**，并包含 `4.3.2` 小节
- 如果之后新增 `704-4.3.3.md`，应直接新增该文件，并保留 `703-4.3.2.md`

---

### 额外提醒

- 默认保留历史 patch 文件，不要因为新增了 `4.3.4` 就删除 `4.3.3`
- 如果未来确实需要清理旧文件，必须由用户明确下指令，不能自行假设
